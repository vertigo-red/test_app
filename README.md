# Тестовое приложение для хранения заметок «Notes»

---

## Что нужно знать о приложении

### Запуск

```
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### Переменные окружения

Значений по умолчанию для параметров подключения к БД нет: без них приложение
завершится с ошибкой конфигурации.

| Переменная       | Обязательна | По умолчанию | Назначение                                                                                                 |
| -------------------------- | ---------------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`           | см. ниже         | —                      | Строка подключения целиком, например`postgresql+psycopg2://user:pass@host:5432/db` |
| `POSTGRES_HOST`          | да¹                 | —                      | Хост БД                                                                                                        |
| `POSTGRES_PORT`          | нет                 | `5432`                | Порт БД                                                                                                        |
| `POSTGRES_DB`            | да¹                 | —                      | Имя базы                                                                                                      |
| `POSTGRES_USER`          | да¹                 | —                      | Пользователь                                                                                             |
| `POSTGRES_PASSWORD`      | да¹                 | —                      | Пароль                                                                                                         |
| `APP_NAME`               | нет                 | `notes`               | Имя приложения в логах                                                                            |
| `LOG_LEVEL`              | нет                 | `INFO`                | Уровень логирования                                                                                |
| `SHUTDOWN_DELAY_SECONDS` | нет                 | `3`                   | Пауза после SIGTERM перед закрытием пула соединений                            |
| `DB_CONNECT_TIMEOUT`     | нет                 | `5`                   | Таймаут одной попытки подключения к БД, сек                                      |

¹ Задайте либо `DATABASE_URL`, либо все четыре переменные `POSTGRES_*`.

### Endpoints

| Метод | Путь            | Описание                                                                                                 |
| ---------- | ------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/`               | HTML-страница со списком заметок и формой добавления                    |
| `GET`    | `/api/notes`      | Список заметок (JSON)                                                                               |
| `POST`   | `/api/notes`      | Создать заметку:`{"title": "...", "body": "..."}`                                                |
| `DELETE` | `/api/notes/{id}` | Удалить заметку                                                                                    |
| `GET`    | `/healthz`        | Liveness: отвечает`200`, пока процесс жив; в БД не ходит                       |
| `GET`    | `/readyz`         | Readiness:`200`, если БД доступна, иначе `503`                                            |
| `GET`    | `/slow?seconds=N` | Запрос длительностью N секунд — удобно для проверки graceful shutdown |

### Особенности поведения, важные для задания

* **Приложение не ждёт базу самостоятельно.** Если на старте PostgreSQL
  недоступен, процесс пишет ошибку в лог и завершается с кодом `1`.
  Ожидание готовности БД — ответственность инфраструктуры.
* **Схема БД создаётся автоматически** при старте (`CREATE TABLE IF NOT EXISTS`),
  миграции запускать не нужно.
* **Graceful shutdown:** по `SIGTERM` приложение перестаёт принимать новые
  соединения, дорабатывает активные запросы, выдерживает паузу
  `SHUTDOWN_DELAY_SECONDS` и закрывает пул соединений с БД. В логах это видно по
  строкам `shutdown signal received` → `shutdown complete`. Если приложение
  не завершится за `stop_grace_period: 75s`, Docker остановит контейнер
  принудительно; причину нужно искать в логах.
* Логи приложения пишутся в `stdout`. Логи Uvicorn доступны через
  `docker compose logs` (`stdout` и `stderr`).

### Локальный запуск без Docker (если нужно посмотреть, как работает)

Потребуется запущенный PostgreSQL.

```
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
export POSTGRES_HOST=localhost POSTGRES_DB=notes POSTGRES_USER=notes POSTGRES_PASSWORD=secret
uvicorn app.main:app --reload
```

## Запуск в Docker Compose

### Запуск

Нужны Docker Engine с Compose и доступ к реестру образов. При первом запуске
в корне репозитория создайте локальный `.env` и задайте в нём пароль; готовый
пароль в Git не хранится. После этой подготовки стек запускается одной командой:

```sh
cp .env.example .env
# Отредактируйте .env: задайте POSTGRES_PASSWORD
docker compose up --build -d
docker compose ps
curl -f http://127.0.0.1:8000/readyz
```

Интерфейс: http://127.0.0.1:8000/ (или порт `APP_PORT` из `.env`). `docker compose logs -f app` показывает запуск и остановку. Обычная остановка: `docker compose down`; данные PostgreSQL останутся в томе `pgdata`. Команда `docker compose down -v` **удаляет данные**.

### Решения

- Multi-stage образ устанавливает закреплённые в `requirements.txt` зависимости в виртуальное окружение и переносит его в финальный `python:3.12-slim-bookworm`. Приложение работает под UID/GID 10001. Образ копирует только каталог `app/`, поэтому `.env` не попадает в слои; `.dockerignore` исключает его из контекста сборки, а исходный `.gitignore` — из Git.
- Compose ждёт успешного `pg_isready`, а скрипт внутри образа дополнительно подключается с реальными реквизитами и выполняет `SELECT 1`. У него есть предел ожидания 60 секунд (`DB_WAIT_TIMEOUT`), после чего процесс завершится с ошибкой и политика `restart: on-failure` повторит запуск. Такой образ сохраняет ожидание БД и при запуске вне Compose, в том числе в Kubernetes. Приложение затем само создаёт таблицы.
- Uvicorn запускается через `os.execvp` как PID 1, получает `SIGTERM` непосредственно и выполняет shutdown приложения. `stop_grace_period: 75s` даёт завершиться запросу `/slow?seconds=60` и штатной паузе 3 секунды.
- PostgreSQL не публикуется на хост; порт приложения доступен только через `127.0.0.1`. База сохраняет данные в именованном томе. Для PostgreSQL healthcheck проверяет приём соединений, для приложения `/readyz` проверяет доступность БД; `/healthz` предназначен для liveness и не проверяет БД. В других оркестраторах можно назначить эти два пути отдельными пробами.
- Пароль задаётся в локальном `.env` и передаётся обоим сервисам как переменная окружения; строку `DATABASE_URL` приложение собирает само. `.env.example` содержит лишь пример: перед запуском замените его пароль.
